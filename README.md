# Everty MultiLink

Нативный Windows-прототип по `firts_tz.md`: Rust + локальная библиотека EvertyUI.
Интерфейс на русском, английском, немецком, испанском и китайском; по умолчанию выбирается язык системы, для неподдерживаемых языков — английский. Язык меняется в настройках без перезапуска. Тёмная тема, без WebView.

Слева есть «Инструкция» с восемью подробными разделами на всех поддерживаемых языках. В списках серверов, правил и подписок доступны перетаскиваемые полосы прокрутки. Первый пункт меню трея подключает или отключает VPN. Подключение из компактного окна сохраняет компактный режим и после запроса прав администратора для TUN.

В «О нас» указаны автор Arthur Valiev и ссылка на https://desk.everty.ru/opensource.
Интерфейс использует единый набор SVG-иконок с подсказками; основные действия остаются текстовыми. Во вкладке «Доступ» можно активировать шестизначный ключ для встроенного сервера `https://multilink.tolkovmeste.com`, проверить срок и обновить серверы. При первом запуске без серверов открывается эта вкладка. Подробнее: [доступ и формат конфигурации](docs/access.md).
HTTPS-подписки теперь сохраняются как отдельные источники: можно обновлять их, менять название или ссылку и удалять вместе с принадлежащими им серверами. Общие узлы и серверы, добавленные вручную, при удалении источника сохраняются. Старые импорты не содержали ссылок: для управления таким источником нужно добавить HTTPS-ссылку снова.

Списки обычных HTTPS-подписок обновляются при запуске и каждые 6 часов, пока клиент работает. Круговая стрелка рядом с подпиской запускает обновление вручную. При сбое сохраняется последний рабочий список; изменения во время VPN-сессии вступают в силу при следующем подключении.

При первом запуске этой версии добавляются начальные DIRECT-маршруты для набора RU-сайтов, `.ru` и `.рф`. Существующие привязки этих правил не перезаписываются; после ручного удаления правила не появляются заново.

В этом репозитории находится только клиент. Сервер управления узлами и выдачи конфигов разрабатывается отдельно. Собственный формат `everty.multilink` v1 поддерживается клиентским импортом наряду с прежними форматами.

## Запуск

Нужны Rust stable и Visual Studio Build Tools с компонентами C++.

```powershell
cargo run -p multilink-app
```

Для готового исполняемого файла:

```powershell
cargo build --release -p multilink-app
.\target\release\multilink-app.exe
```

Для реального подключения поместите официальный `mihomo.exe` в
`vendor/mihomo/` или задайте переменную `MULTILINK_MIHOMO` с полным путём.
Приложение не скачивает и не устанавливает ядро автоматически.
[Официальные сборки Mihomo](https://github.com/MetaCubeX/mihomo/releases).

1. В компактном окне нажмите «Расширенные настройки», затем откройте
   «Подписки» → «Импорт подписки».
2. Вставьте HTTPS URL, VLESS-ссылки, Base64-список или Mihomo YAML.
3. Выберите политику на экране «Маршрутизация».
4. На странице «Маршрутизация» добавьте домены/IP/CIDR или набор «RU сайты»;
   для каждого правила выберите прямой маршрут, общий VPN, страну или конкретный сервер.
5. Нажмите круг подключения в компактном окне или кнопку на экране обзора.
6. Системный прокси Windows включится автоматически. В настройках можно
   отключить «Авто» и использовать `127.0.0.1:17890` вручную в нужном приложении.

Поле импорта поддерживает Ctrl+V, Ctrl+A, навигацию и редактирование клавиатурой;
Enter применяет, Esc закрывает окно. Большой список прокручивается колесом мыши.
Нажатие на строку сервера включает или исключает его из пула.
Импорт/включение узлов и смена режима System Proxy доступны при отключённом ядре.
Исключения и политику маршрутизации можно менять во время подключения.

«Маршрутизация → Antigravity» открывает шаблон правила для `Antigravity.exe`.
Выберите конкретный включённый сервер и нажмите «Проверить регион». Пробный POST
идёт через этот сервер, без переключения текущего VPN и без данных аккаунта.
Сообщение об отсутствии блокировки означает, что пробный ответ не содержал явного
запрета региона; оно не подтверждает возможность входа в аккаунт. Для охвата трафика
приложения по имени процесса используйте TUN.

Закрытие окна прячет приложение в системный трей, сохраняя подключение.
Левый клик по значку открывает окно; правый — меню подключения, выбора размера
окна, быстрого правила и полного выхода. Команда «Правило из буфера…» открывает
полное окно и подставляет текст из буфера обмена. Автозапуск Windows включается
в разделе «Настройки» и запускает приложение скрытым в трее. Само VPN-подключение
при входе в Windows автоматически не включается.

## Что реализовано

- Шесть экранов: обзор, серверы, подписки, маршрутизация, статистика, настройки.
- Импорт VLESS TCP / TLS / REALITY / WebSocket / gRPC, Base64 и YAML `proxies`.
- Проверка импорта, дедупликация параметров соединения. В смешанной URI-подписке
  совместимые узлы добавляются, несовместимые пропускаются с числом и причинами
  в журнале статистики. Полностью невалидный импорт не меняет библиотеку.
- Для URI неизвестные параметры отклоняются с сообщением; не происходит тихой
  замены неподдерживаемого транспорта на TCP. YAML сохраняет поля узла;
  окончательную совместимость конфигурации проверяет само ядро при запуске.
- `spx` принимается и сохраняется как исходный SpiderX-путь: Mihomo не имеет
  соответствующего поля, поэтому в его конфигурацию этот параметр не передаётся.
  `support-x25519mlkem768` сохраняется в `reality-opts`. XHTTP и `fm` пока
  несовместимы с этим импортёром: такие узлы явно отмечаются как пропущенные.
- Один управляемый процесс Mihomo, фоновые операции без блокировки интерфейса.
- Локальный HTTP/SOCKS5, controller API только на loopback со случайным токеном.
- Автоматический системный прокси текущего пользователя Windows (WinINet/LAN):
  HTTP и HTTPS через `127.0.0.1:17890`, без прав администратора. Включается
  только после готовности Mihomo; настройки восстанавливаются до остановки ядра.
  Сохраняются адрес прокси, исключения, PAC URL и флаги автоопределения.
  Журнал восстановления защищён DPAPI и записывается до изменения Windows.
  Отдельный watchdog восстанавливает настройки при аварии владельца; при старте
  приложение повторяет восстановление незавершённой сессии. Если пользователь
  или другой VPN изменил настройки после включения, это изменение сохраняется.
  Одновременное управление прокси из двух экземпляров MultiLink блокируется.
  Windows Job Object завершает собственный Mihomo при аварии приложения.
- `load-balance / round-robin`, `url-test` с tolerance 50 мс, `fallback`.
- Проверки доступности средствами Mihomo каждые 60 секунд.
- Правила `DOMAIN-SUFFIX`, IPv4/IPv6 и CIDR могут отправлять запросы напрямую,
  через общий пул или через выбранную страну. Страны определяются по флагу либо
  распознаваемой подписи в имени включённого узла, без геолокации и отправки
  подписок третьим лицам. Неоднозначные узлы не включаются в страновые группы.
  Если для выбранной страны нет включённых серверов, конфигурация отклоняется.
  Для широкого набора российских сайтов есть готовое правило «RU сайты»,
  включающее .ru, .рф и локальный набор MetaCubeX для доменов в других зонах.
  Персональное правило сайта имеет приоритет над широким набором.
  Источник, версия, хеш и лицензия набора приведены в [assets/README.md](assets/README.md).
  Репозиторий набора использует GPL-3.0; перед распространением приложения с
  встроенным набором необходимо проверить применимые условия лицензии.
  Можно вставить URL целиком: путь и порт отбрасываются, используется домен.
  Поддерживаются IDN и `*.example.com`. IP-правила разрешают DNS, чтобы IP/CIDR
  совпадал и при запросе браузера по имени сайта; старые `no-resolve` исправляются.
  Изменения применяются через controller API без перезапуска Mihomo и сброса
  System Proxy. Настройки сохраняются после подтверждения ядра. Если ядро
  отклоняет конфигурацию, новая версия не становится сохранённой рабочей.
  Уже открытые соединения, совпадающие с изменёнными правилами, закрываются
  для повторного выбора маршрута. Другие соединения не закрываются.
  Если у старого туннеля нет известного IP для нового IP-исключения, интерфейс
  просит обновить вкладку: правила гарантированно действуют на новые соединения.
- Фактические счётчики соединений, объём и график трафика из `/connections`.
  Скорости вычисляются по приращению счётчиков и времени между замерами.
  RTT берётся из истории проверок ядра. До подключения показывается «—».
- Сохранение узлов, политики и исключений в Windows DPAPI для текущего пользователя.
- Завершение дочернего процесса и удаление временного YAML при обычном закрытии.

Балансировка следует [документации Mihomo](https://wiki.metacubex.one/en/config/proxy-groups/load-balance/),
телеметрия — [controller API](https://wiki.metacubex.one/en/api/).

## Границы прототипа

Это начальный работающий каркас, **не весь MVP из ТЗ**.
TUN, kill switch,
собственный Smart Balance с историей ошибок/гистерезисом, обновление подписок
по расписанию, статистика трафика по отдельным узлам и установщик ещё не реализованы.
Название Smart Balance пока соответствует штатному round-robin Mihomo.
Maximum Speed не добавлен: RTT не позволяет достоверно оценивать пропускную способность.
Bonding одного потока не заявляется и не реализован.

Адрес источника подписки пока не сохраняется: импорт дополняет локальную библиотеку,
повторный импорт не удаляет старые узлы. Для полного обновления можно сначала
очистить пул в настройках. Перенаправления HTTPS отклоняются; нужен конечный URL.
В локальной библиотеке пока нет поиска/фильтрации и редактирования отдельных узлов.

Правила DIRECT явно обходят прокси. Без них последнее правило — MULTILINK;
автоматического fallback на DIRECT нет. Это не защита всего трафика Windows:
локальный прокси не контролирует приложения, которые не используют его, DNS и IPv6 ОС.

Настройки находятся в `%LOCALAPPDATA%\Everty\MultiLink\state.dpapi`.
Предыдущая версия хранится в `state.previous`. Runtime-конфигурация Mihomo должна
содержать открытые учётные данные и находится в подпапке `runtime` текущего
пользователя на время работы; после аварийного завершения может остаться на диске.
Механизм DPAPI не заменяет будущую изоляцию runtime-файлов.
Журнал системного прокси хранится рядом в `system-proxy.dpapi` и удаляется после
восстановления. Watchdog не требует UI и не захватывает экран. System Proxy
применяется к стандартному LAN-подключению текущего пользователя; отдельные
RAS/VPN-профили и машинный WinHTTP не изменяются. При аварии прокси возвращается
к исходным настройкам; это восстановление доступности, а не kill switch.
Если watchdog был принудительно завершён вместе с приложением, повторный запуск
выполнит восстановление из журнала.
На Linux/macOS интерфейс и архитектура переносимы, но защищённое хранилище
сейчас вернёт ошибку: нужны Keychain/Secret Service адаптеры.

## Структура и проверка

Интерфейс обновляется по событиям ввода и сообщениям фонового потока, без
постоянной перерисовки в простое. Разметка текста кэшируется, а поле импорта
формирует только небольшое видимое окно текста даже при большой вставке.
Сохранение DPAPI вынесено из UI-потока. Кнопки и строки имеют hover/pressed
состояния; недоступные действия визуально выключены и не принимают клики.
Каретка устанавливается кликом, доступны Ctrl+C/X/V/A и Shift+стрелки.
Профиль `cargo run` оптимизирован для программного рендеринга.

Замер отрисовки без вывода на экран: `cargo run -p multilink-app -- --bench-ui`.
Диагностика подписки без сохранения: передайте URL или тело в stdin команды
`cargo run -p multilink-mihomo --example check_subscription`. Она печатает
только количество совместимых узлов и причины пропуска, без учётных данных.

```text
crates/multilink-app       EvertyUI, winit, окно, экраны и фоновые команды
crates/multilink-core      модель, импорт, дедупликация, проверка правил
crates/multilink-mihomo    конфигурация, процесс, controller API
crates/multilink-platform  Windows DPAPI и каталог данных
EvertyUI                  исходная UI-библиотека
vendor/mihomo             место для внешнего ядра
```

```powershell
cargo fmt --all --check
cargo check --workspace
cargo test --workspace
cargo run -p multilink-app -- --preview preview.png
```

Ручные проверки на отключённом приложении:

```powershell
cargo run -p multilink-platform --example system_proxy_check
cargo run -p multilink-mihomo --example lifecycle_check
cargo test -p multilink-mihomo real_mihomo_routes_http_connect_and_live_exceptions -- --ignored
cargo run -p multilink-app -- --smoke-tray
```

`system_proxy_check` кратковременно переключает реальный пользовательский прокси,
проверяет обычное восстановление, блокировку второго владельца и восстановление
watchdog после принудительного завершения тестового процесса. Исходные значения
не печатаются. `lifecycle_check` проверяет API установленного Mihomo и завершение
ядра вместе с аварийно остановленным владельцем; системный прокси не меняет.
Последняя команда проверяет реальные HTTP/CONNECT-запросы через Mihomo, добавление
и удаление DIRECT-исключений на работающем ядре, закрытие совпавшего туннеля,
DNS-сопоставление IP и отказ от повреждённой конфигурации. Тестовые HTTP, VLESS
и DNS серверы работают только на loopback; пользовательские подписки и настройки
Windows в этом тесте не используются.
`--smoke-tray` создаёт скрытое тестовое окно, проверяет значок в трее,
переключение размеров и скрытие по закрытию; экран не считывается.

Windows-интеграция использует [WinINet per-connection options](https://learn.microsoft.com/en-us/windows/win32/api/wininet/ns-wininet-internet_per_conn_optionw).

Параметр после пути выбирает экран для отрисовки без открытия окна:
`servers`, `subscriptions`, `routing`, `statistics`, `settings`.
Сетевые критерии приёмки требуют настоящей подписки и установленного ядра;
модульные тесты не заменяют такой прогон.


### Маршруты, заметки и перенос конфигурации

В редакторе правила можно вводить несколько доменов/IP или имён `.exe` через
запятую, точку с запятой или перенос строки. Список проверяется целиком перед
применением; для каждого значения создаётся отдельное правило с общим маршрутом
и заметкой. Кнопка «Заметка…» открывает поле пояснения; изменения заметок и правил
сохраняются после подтверждения ядра, если подключение активно.

«Экспорт» сохраняет JSON версии 1: правила, политику и заметки. Паролей, подписок
и конфигурации серверов в файле нет. «Импорт» проверяет файл до применения,
позволяет дополнить список (совпадения обновляются) либо явно заменить его целиком.
Привязки к отсутствующим/выключенным серверам или странам сохраняются, но во время
подключения временно используют общий VPN-пул с предупреждением. DIRECT для
такого fallback не используется; включите нужный узел и переподключитесь, чтобы
вернуть сохранённую привязку.

### Умный выбор и оценка серверов

Политика «Умный выбор» включается через «Сменить» в маршрутизации/настройках.
Общий пул использует URL-проверки каждые 30 секунд с допуском 100 мс для
переключения. До 32 явных доменных правил с маршрутом MULTILINK получают отдельные
URL-test группы: `https://домен/`, проверка раз в 60 секунд при использовании
группы, тайм-аут 4 секунды. Успешными считаются HTTP 200–399, 401 и 404; 403/429,
сетевые ошибки и тайм-ауты считаются неудачами. Поэтому разные сайты могут
использовать разные узлы. Явная привязка к серверу/стране и DIRECT имеют приоритет.
Проверки не повторяют POST-запросы, пароли, куки или авторизованные действия.
Корневой URL не доказывает доступность каждого API, аккаунта или функции сайта.
Работающие соединения не обрываются специально; новый маршрут применяется к новым.

Оценка 0–100 — сглаженная успешность проверок, задержка и её колебания. Опрос API
не считает один и тот же замер повторно. До трёх наблюдений оценка помечена «≈»;
история сохраняется периодически. «Сортировать по оценке» меняет только порядок
отображения; оценка является индикатором, URL-test выбирает рабочие узлы по
актуальным URL-проверкам и допуску. Узлы RU остаются вне общего VPN-пула.
